# decision-aperture

A CC0 decision-aperture layer for AI-assisted software development.

Sibling to `vibe-code-audit`, `method-layer`, and the `Simulators` tree.
Where `vibe-code-audit` measures the **link surface** of code that
already exists, `decision-aperture` measures the **decision surface** of
a request before the code is written -- and treats the usefulness of
its own questions as an **experimental variable**, not a design
assumption.

Its purpose is one sentence: **help identify implementation-bearing
decisions that have not actually been made yet, and measure which
questions actually help THIS human-AI-project-constraint
configuration.**

CC0. Python 3 standard library only. No network. Parses under 3.9.
Phone-buildable.

```
python3 assessment_frame.py --new frame.json
python3 assessment_frame.py frame.json --set human solo_dev
python3 assessment_frame.py frame.json --add-instrument X scanner ./x.py api_shape
python3 assessment_frame.py frame.json --route persistence

python3 aperture_scan.py "add caching to the app"
python3 decision_ledger.py --new "request text" --frame frame.json
python3 decision_ledger.py LEDGER --resolve D2 --by user --answer "redis"
python3 decision_ledger.py LEDGER --report

python3 usefulness_lab.py run --frame frame.json \
    --question "..." --surface caching \
    --profile-a fixtures/cache_profile_a.py \
    --profile-b fixtures/cache_profile_b.py \
    --friction low --out experiment.json
python3 usefulness_lab.py compare exp1.json exp2.json

python3 test_aperture.py    the checks; prints their count
```

---

## What it is not

It is **not a requirements generator** -- a request with zero detected
surfaces is reported as `UNMAPPED`, first line, not padded. It is
**not an opinionated framework** -- it carries no preferred stack,
pattern, or methodology. It is **not the coding agent** -- it never
writes the implementation. And it **does not define "helpful question"
universally** -- usefulness is measured per frame, not asserted.

## The assessment frame

Every question, decision, and observation is scoped to an
**assessment frame**: the specific configuration of

- **human** (who is asking)
- **AI/model** (which system is implementing)
- **project** (greenfield script, legacy monolith, library)
- **environment** (local, CI, restricted egress)
- **constraints** (time, compliance, hardware)
- **available instruments** (scanners, test runners, auditors)
- **knowns / unknowns / unverified areas** (epistemic state)

Fields may be `UNMAPPED` (not provided) or `UNMEASURED` (declared but
not probed). Those are states, not errors. Routing a decision surface
returns instruments **in this frame** or `FRAME_UNMAPPED` -- never a
nearest guess, never a universal recommendation.

## Decision states

| state | meaning |
|---|---|
| `DETECTED` | surface located; nothing more known |
| `UNRESOLVED` | exposed and decomposed; no answer on record |
| `RESOLVED` | answer on record **with provenance** |
| `DEFERRED` | explicitly postponed -- recorded, scored as owned |
| `UNMAPPED` | request text matched no registry surface |
| `UNMEASURED` | question generated but discriminating power untested |
| `NOT_APPLICABLE` | surface bears no implementation consequence here |

## Operations it may perform

**detect**, **expose**, **decompose**, **ask** (budgeted), **route**
(consequence class + frame instruments), **record provenance**.

## Operations it must not perform

**It must not silently resolve a decision.** There is exactly one door
into `RESOLVED`, and it requires an answer and a named author. **It
must not substitute a default for something unknown.** The ledger
schema carries no default field; unresolved surfaces print **first**
in the report. **It must not rank questions universally.** A
comparison across frames reports deltas and frame differences, and
states that a delta is not evidence one question is universally
better.

## The experimental protocol: usefulness as a variable

A question generated by `aperture_scan` is a hypothesis. The test:

1. Fix an assessment frame.
2. Ask the question.
3. Produce implementations under two different answer profiles.
4. Measure structural divergence (`discriminate.py`).
5. Measure friction (cost of asking/answering).
6. Compute actual usefulness transparently: `divergence -
   friction_penalty`, clamped, with the explanation printed.
7. Record the full experiment: frame, profiles, artifacts,
   measurements, observations, deviations, unmeasured areas.
8. Repeat under another frame. The delta is evidence about whether
   usefulness is frame-dependent.

A question that fails to discriminate in one frame is marked
`registry_suspect` **in that frame's ledger**, with the report
explicitly noting this is frame-local evidence, not a universal
verdict.

## The instrument measures itself

The same posture as the move-set garbage-ledger finding: the
instrument's reward attacked by the instrument. The shipped demo
shows the caching-scope question discriminating (divergence 0.7419)
and a wording-level question not discriminating (0.0), both under
recorded frames. The comparison report states what the delta does
and does not mean.

## The limit, stated here rather than at the bottom

`aperture_scan.py` is a **word list**; paraphrase steps around it.
`discriminate.py` measures **structural** divergence (AST/token
multiset), not behavioral divergence; that false negative is named in
every verdict. `assessment_frame.py` records **declared** facts;
instrument availability is `UNMEASURED` until exercised. The registry
is not a completeness claim. A zero is a property of the measurement,
not the world.
